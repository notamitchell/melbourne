# eMelbourne

A rebuild of [eMelbourne: the city past and present](https://www.emelbourne.net.au/), the online
Encyclopedia of Melbourne, as a plain static website. All 3,391 records from the original database
are stored as TEI XML, one file per record, and rendered in the browser with no server and no
framework.

- **To look at it:** download the repository (green **Code** button, then **Download ZIP**), unzip
  it and double-click `site/index.html`.
- **To publish it:** copy the `site/` folder to any static web host (GitHub Pages, Netlify,
  Cloudflare Pages, Apache, nginx, an S3 bucket). There is no build step.
- **To edit entries:** see [EDITING.md](EDITING.md).

The live preview is on GitHub Pages at <https://notamitchell.github.io/melbourne/>, published by
`.github/workflows/deploy-pages.yml` after every change to `main`. That workflow is the only
Pages-specific file; delete it to move to another host.

## Repository layout

```
site/

  entry.html        renders any entry: entry.html?id=EM00187 (loads tei-js/EM00187.js)
  page.html         About, Help and the exhibitions: page.html?p=about, ?p=everydaywar-women (tei/pages/*.xml)
  object.html       one OHRM digital object (picture, letter, record): object.html?id=D00000891
  browse.html       A to Z by type and letter
  search.html       full-text search over data/index.js
  advanced.html     faceted search over data/facets.js; rebuild with python3 tools/build-facets.py after TEI changes
  404.html          old-URL shim: /biogs/EM00187b.htm -> entry.html?id=EM00187
  js/tei.js         TEI -> HTML renderer (DOMParser, ~150 lines, no dependencies)
  js/app.js         entry page, search, browse
  css/site.css
  tei/              one TEI file per entity (the source of truth)
  tei-js/           the same TEI wrapped as EMEL.loaded("tei:EM…", "<TEI…>") so it loads
                    with a <script> tag; generated by convert.py, never edit by hand
  data/index.js     search/browse index (name, type, author, dates, themes, plain text)
  data/names.js     id -> name for every entity, so links to unconverted records get a label
  data/nav.js       theme menu in the old site's order (from HTMLVARIABLES $nav), page list, In Focus
  data/objects.js   all 1,561 digital objects: title, description, dates, rights, linked entries,
                    PROV citation for the Everyday War letters, image paths where the archive has them
  objects/          images that exist in the figshare archive
tools/convert.py    database -> TEI + JSON (Python stdlib only, uses the psql client)
tools/validate.sh   checks every TEI file against schema/emelbourne.rng (needs Java + jing)
tools/build_index.py  tei/*.xml -> tei-js/, data/index.js, data/names.js (Python stdlib only)
tools/apply_leftovers.py  attaches the OHRM records kept in the tidy-up (enrichments/leftovers/): references in 4 entries,
                    the Further Reading page, and each object's archival source in data/objects.js (re-runnable)
tools/prov_links.py   matches the Everyday War letters to PROV catalogue records -> enrichments/prov-links.csv
tools/apply_prov_links.py  writes the matched links into tei/pages/*.xml and data/objects.js (re-runnable);
                    then run build_index.py
tools/enrich.py     review|apply: suggests people-mention and birth/death-place links, written into tei/ only
                    for rows marked y in enrichments/review.csv; then run build_index.py and build-facets.py
schema/             emelbourne.odd (the entry format, documented) and emelbourne.rng (generated: tools/build_schema.py)

```

## Editing entries

`site/editor.html` (double-click it, or open it on the site) opens an existing entry or starts a
new one, edits it (Quill for the article; pasted Trove, SLV, PROV, UoM and IIIF links become
images), previews it with the site's own renderer, compares it with the version it started from,
and saves `tei/<ID>.xml` and `tei-js/<ID>.js` as downloads. It edits the TEI in place: only the
parts the editor changed are rewritten, so everything else in the file is kept exactly as it was.
Collaborators then upload the two files through the GitHub website (step by step: `EDITING.md`).
`.github/workflows/rebuild-index.yml` runs `tools/build_index.py` and `tools/build-facets.py` on every change to
`site/tei/`, commits the rebuilt wrappers and search indexes, and validates the TEI. Without GitHub Actions, run
`python3 tools/build_index.py && python3 tools/build-facets.py` by hand (Python 3 standard library only).
The editor's code is adapted from Carlton's contribution
form (`site/js/glam-embed.js` and `site/js/tei-compare.js` come from there; Quill 1.3.6 is in
`site/js/vendor/quill/` so the editor works offline).

## Regenerating

**`site/tei/` is now the master copy.** People edit those files (by hand, in the editor, or with
reviewed enrichment scripts), so do not re-run `convert.py` over `site/` any more: it would
overwrite those edits. The steps below are kept to document the one-time import, and can be
run into a different `--out` folder for comparison.

1. Download and unzip the figshare RO-Crate (doi:10.26188/23983911.v1).
2. Load the dump: `createdb emel && cd ohrm/web/sql && psql emel -f createOHRM.sql -f updateEMEL.sql`
   The `WW1-P0000/1` tables fail to load because of the hyphen in their names. They hold the Public
   Record Office Victoria citations for the Everyday War letters, so load them under new names:
   `sed -n '/TABLE WW1-P000[01]/,$p' EMELdat2013.sql | grep -E '^(CREATE|INSERT|[[:space:]]|\))' | sed 's/WW1-P000\([01]\)/ww1_p000\1/' | psql emel`
   (optional: without them the object pages just omit the PROV reference).
3. `python3 tools/convert.py --db emel --out site --objects /path/to/unzipped/crate --ids EM00187,EM00018`
   or `--all` for every record.

## TEI format

Entries use the Carlton Common Ground entry format (`schema/carlton.odd` in the historicalesque/carlton repository),
so the two sites can share a renderer and an editor. `schema/emelbourne.odd` is the eMelbourne
variant and documents the differences: `TEI/@type` also allows `object` (cultural artefacts),
`TEI/@subtype` records the OHRM type (entry, theme, person, place, cultural-artefact, concept,
event, page), `idno type="entry"` holds the OHRM id, and links and image paths are relative to the
TEI file. In short:

```
<TEI type="person|place|topic|object" subtype="entry|theme|...">
  teiHeader   title, authors, idno, licence, one <change> per event in the record's history
  standOff    the subject (person/place, xml:id="subject"), chronology, links (listRelation)
  text        body: div type="detail" (the article), div type="gallery"; back: bibliography
```

All 3,391 records and the 22 site pages validate against `schema/emelbourne.rng`, which is generated from
`emelbourne.odd` by the TEI Stylesheets (v7.61.0, TEI P5 4.12.0): `python3 tools/build_schema.py <stylesheets folder>`
(needs `pip install saxonche`; the setup steps are at the top of that script). Run it after editing the ODD.

## Navigation

Rebuilt from the old site, as described on its Help page: a title banner (Home, About, Help,
quick search) and three content tabs (Themes, A to Z, Search). The 21 themes and their order
come from the menu stored in the database. Home, About and Help come from the HTMLADDITIONAL
table and are converted to TEI like the entries. Their images were not in the archive and are
hidden until recovered.

The old site's extra pages are converted too: the 15-page Everyday War exhibition
(`everydaywar*`), Civic Treasures, Letterheads and In Focus. They appear under "Exhibitions" in
the side panel. Their long object lists came from template variables (`$CivicTreasures-Dobjects`
etc.), which `convert.py` expands before converting. Objects link to `object.html`.

## Notes

- The 404 shim needs the host to serve `404.html` for missing paths (GitHub Pages, Netlify and
  Cloudflare Pages do this by default; Apache: `ErrorDocument 404 /404.html`; nginx: `error_page 404 /404.html`).
  If the site is served from a sub-path, set `SITE_ROOT` in `404.html` (the Pages workflow does this
  for GitHub Pages automatically).
- Why `tei-js/`: browsers block `fetch()` of local files, so a double-clicked site cannot read
  `tei/*.xml` directly. `<script>` tags are allowed from disk, so each TEI file is also written as a
  small JS wrapper. The `.xml` files stay the master copy; `convert.py` regenerates the wrappers.
- Pages need JavaScript; `tei/` stays readable without it.
- PROV links: 649 of the 688 Everyday War letters link to their PROV catalogue record (citation "VPRS 3183/P0001,
  YY/NNNN", with YY taken from the letter's date). PROV has not digitised these consignments, so there are no images.
  The content tidy-up findings are in `enrichments/leftovers/TIDY-UP.md`.
- Experiments (`site/experiments/`) use D3 7.9.0 from `site/js/vendor/d3/` (ISC licence), so they work offline too.
- Tested via file:// in Chromium, Firefox and WebKit (Safari's engine), with Playwright: pages, search, advanced
  search, the editor (open, edit, save) and the experiments. An axe-core WCAG 2.1 AA check of 26 page types, in
  light and dark mode, reports no violations.
